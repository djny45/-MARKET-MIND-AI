# MARKET MIND AI — 3D Research Terminal (standalone landing page)

A **separate, self-contained Next.js application** inside the MARKET-MIND-AI
repository. It is a research/education interface: a 3D Gateway Flow shader
stage behind a dense financial terminal with six working panels and 550
**generated** specialist agent profiles.

> **Data honesty:** all prices, agent metrics, P&L, accuracy figures and signals
> shown here are **simulated / generated by the local engine**. They are not
> verified live prices and not independently verified AI performance. No broker
> execution, order routing, wallet handling or live trading exists in this app.

## Location and independence

```text
landing-pages/motion-ai-3d-terminal/   <-- this app (Next.js 16)
frontend/                              <-- existing MARKET-MIND-AI Vite UI (untouched)
backend/                               <-- existing FastAPI research backend (untouched)
```

This app is self-contained at runtime. It does not require the backend to run.
Seven-market work added a metadata-only coverage report and reference entries
to the shared backend instrument catalogue (`backend/app/markets.py`,
`backend/app/instruments.py`); no existing frontend, hosting or production
configuration was changed. Run commands **from this directory**, not the
repository root.

## Seven-market research coverage

The terminal renders seven research desks from one synthetic registry:
**gold, silver, crude, forex, USA, India and crypto** (18 instruments, seven
session calendars). Silver adds XAG/MCX-silver instruments and the gold/silver
ratio rationale; crude adds WTI, Brent and MCX-crude. All values are
deterministic `demo-synthetic` fixtures — not live prices, not trading signals.
The backend reports the same seven-market taxonomy at `GET /api/markets` under
`seven_market_coverage`; its entries are reference metadata only, with no
quote, entitlement or ingestion implied.

### Environment variables

| Variable | Required | Purpose |
| --- | --- | --- |
| `DATABASE_URL` | No | PostgreSQL connection string. If unset/unreachable the app still boots in labelled read-only synthetic demo mode; `/api/health` reports the real state and data endpoints return HTTP 200 with `dataOrigin: "demo-synthetic"`. |
| `DATABASE_TIMEOUT_MS` | No | Hard deadline for every browser-facing database request (default 4000 ms), applied by `withDatabaseTimeout()` on all data routes. Prevents an unreachable database from hanging the page forever. |
| `MARKET_MIND_API_URL` | No | Optional FastAPI backend base URL. Empty = fully self-contained local demo. |
| `MARKET_MIND_API_TOKEN` | No | Optional bearer token for a backend that requires it. Never commit. |
| `MARKET_MIND_API_TIMEOUT_MS` | No | Backend probe timeout, default 5000 ms. |
| `MARKET_MIND_RESEARCH_DB` | No | Explicit path to a local backend SQLite DB for operator-attested `binance-public` research bars. Separate from `DATABASE_URL`; read-only, off by default. Never use in a public deployment. |

## PostgreSQL setup and Drizzle migrations

The ZIP shipped a hardcoded local development URL in `drizzle.config.json`.
**Do not use it in production.** Set `DATABASE_URL` in your environment and use
the Drizzle kit scripts (from this directory):

```bash
# Create the tables from src/db/schema.ts
npx drizzle-kit push

# Or generate SQL migrations, then apply them
npx drizzle-kit generate
npx drizzle-kit migrate
```

Health check: `curl -s http://localhost:3000/api/health`
returns `{"ok":true,"database":"connected"}` only when `select 1` and a
read-only schema check succeed. Without a database it returns HTTP 503 with
`database:"unconfigured"`, `"unavailable"` or `"schema-incomplete"` — it never
falsely reports a connection. Agent-grid readiness is reported separately in
the `agents` field. Database attempts are bounded by `DATABASE_TIMEOUT_MS`.

Verify the unreachable-database regression:
`node scripts/verify-unreachable-db.mjs` (no credentials used or written).

| GET | `/api/research-bars` | `symbols` (comma list) | Opt-in read-only `binance-public` research bars; `dataOrigin: "binance-public-research"`, with `retrievedAt` and a `stale` flag. Disabled unless `MARKET_MIND_RESEARCH_DB` is set. Not live/execution-grade data. |

## Optional MARKET-MIND-AI backend adapter

`src/lib/marketMindAdapter.ts` is a typed, read-only client using **only
documented endpoints**: `/api/health`, `/api/workers`, `/api/terminal/providers`.
It has a bounded timeout, AbortSignal support, no-store caching, token from
environment only, and reports `disabled | connected | unavailable |
authentication_required`. The header shows this status honestly. It creates no
duplicate agents and no duplicate market data; the local simulation and the
backend remain clearly separated via `dataOrigin`.

## Optional local research bars (opt-in, private use only)

If you set `MARKET_MIND_RESEARCH_DB` to the path of the backend SQLite database,
`GET /api/research-bars` reads only rows with `source='binance-public'` and
`status='live'` (BTC/ETH/SOL/BNB 15m bars) and a small strip shows them with
source, bar timestamp, retrieval time and a staleness warning. This is a
**read-only, server-side** bridge: it never writes, never exposes the file path,
and is disabled by default. These are publicly sourced **research bars, not a
licensed real-time feed and not execution-grade prices**. Do not enable this in
a public deployment; it is intended for a private, single-operator research
environment that has accepted the source terms. It is independent of
`DATABASE_URL`, which remains unset for the demo-mode release.

## Shader integration

See `src/shaders/README.md` for provenance, SHA-256 hashes and integration
notes. `?raw` HTML imports are reproduced for Turbopack by `tools/raw-loader.cjs`
and `next.config.ts`. The authored document loads four CDN scripts (Tailwind,
Iconify, GSAP, ScrollTrigger); if a CDN is unavailable the iframe still renders
its dark stage, but the authored particle animation may not start. The genuine
OFL Fragment Mono latin subset is vendored at
`src/shaders/fonts/fragment-mono.woff2` because the ZIP's CSS references it but
the archive omitted the binary.

## Research-only boundary

Permitted: market observation, price visualisation, historical analysis, agent
and consensus research, simulated backtesting, risk research and data-quality
monitoring. Prohibited and absent: real-money execution, broker routing,
wallet keys, transaction signing, autonomous live trading and live market-making.

## Known limitations / remaining issues

- The original ZIP pin of **Next.js 16.4.2** carried **7 MEDIUM** advisories
  (cookie/header disclosure, SVG DoS, HTTP response desync, cache-key and
  fallback-shell poisoning, cross-request cache dedup race). `next` and
  `eslint-config-next` are now pinned to **16.4.6** (fixed in 16.4.5+):
  `npm audit --omit=dev` reports 0 production vulnerabilities and
  `npm run build` exits cleanly with all routes generated. The remaining
  dev-only `esbuild` advisories under `drizzle-kit` are not shipped in the
  production bundle.
- No PostgreSQL instance was available during validation, so the simulated
  engine's database seeding path was not exercised against a real database;
  the app was verified in its documented database-less fallback state.
- CDN-dependent shader animation was not verified end-to-end offline.
- The optional backend adapter was typechecked and built but not exercised
  against a live authenticated backend during this integration.
