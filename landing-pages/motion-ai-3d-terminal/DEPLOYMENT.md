# Deploying the Motion AI 3D terminal

This app is a **standalone Next.js research demo**. It is deploy-ready but it
is **not** a live market terminal: prices, agent metrics, P&L and signals are
generated by the local simulation engine. The UI footer discloses this.

## What happens at runtime

- **No `DATABASE_URL`** — the app boots into **read-only synthetic demo mode**.
  `/api/health` returns HTTP 503 with `database: "unconfigured"`,
  `demoMode: true` and a remediation hint. The 3D terminal **renders fully**
  using deterministic synthetic data, with a persistent amber banner stating
  "read-only demo mode · database unavailable · synthetic sample data · not
  live market data". All API routes return `dataOrigin: "demo-synthetic"`.
  This is honest, not a broken build, and never claims database connectivity.
- **Database present but unreachable** — same demo-mode fallback with a
  redacted diagnostic in `/api/health`; no secret values are exposed.
- **With `DATABASE_URL`** — tables must exist, then the engine **self-seeds**
  on the first API/page request (instruments, 550 agents, candles, signals).
  No separate seed script is needed. The full 3D terminal renders.

## Deploy to Vercel (recommended)

### 1. Create a PostgreSQL database

Use Neon, Supabase, Vercel Postgres, or any hosted PostgreSQL. Copy the
connection string — it is a secret and must never be committed.

### 2. Create the tables (one time, from your machine or CI)

```bash
cd landing-pages/motion-ai-3d-terminal
npm ci
# Option A: apply the schema directly (development / first deploy)
DATABASE_URL='postgresql://...' npx drizzle-kit push

# Option B: apply the committed, reproducible migration (recommended for prod)
DATABASE_URL='postgresql://...' npx drizzle-kit migrate
```

`drizzle.config.ts` reads `DATABASE_URL` from the environment (or `.env.local`
for local use) and **fails closed** if it is missing — it will never silently
target the old hardcoded localhost URL from the original ZIP. The committed
`drizzle/0000_initial_schema.sql` was generated from `src/db/schema.ts` and
verified with `drizzle-kit generate` ("No schema changes, nothing to migrate").

### 3. Configure the Vercel project

- **Root directory:** `landing-pages/motion-ai-3d-terminal`
  (set this in Project Settings → General so Vercel builds the correct app).
- **Framework:** Next.js (auto-detected; also pinned in `vercel.json`).
- **Build command:** `npm run build` · **Install command:** `npm ci`.
- **Environment variable:** `DATABASE_URL` = your connection string.
  Do **not** add `MARKET_MIND_API_URL` unless you have a reachable FastAPI
  backend; leaving it unset keeps the page fully self-contained.
- Never add secrets to the repository or to client-side `NEXT_PUBLIC_*`
  variables.

### 4. Deploy and verify

```bash
git push origin feature/motion-ai-3d-terminal
# or use the Vercel Git integration / CLI: vercel --prod
```

Then check:

- `GET /api/health` → `{"ok":true,"database":"connected","dataOrigin":"database-simulated"}`
- `GET /` → renders the terminal (first request seeds the database; a slow
  first load is expected)
- `GET /api/market`, `/api/agents`, `/api/signals` → 200 with
  `dataOrigin: "database-simulated"`

To verify either mode against a running server:

```bash
npm run build && npm run start -- -p 3123 &
node scripts/verify-terminal.mjs
```

The harness checks the homepage, demo banner, all API contracts, explicit
data-origin labels and honest health reporting in both modes. It never reads
or prints credentials.

## Other platforms

The same steps work on Netlify, Render, Railway or Fly.io. The only
requirements are Node.js 22+, `npm ci && npm run build`, and a `DATABASE_URL`
pointing at a reachable PostgreSQL instance. Set the build/start commands in
that platform's UI accordingly.

## Boundaries

- No broker execution, wallet keys, transaction signing, or real-money trading.
- No live market feed is claimed. If you later point the backend adapter at a
  real API, keep the existing `dataOrigin` labelling and simulated-data footer.
- The parent repository documents that **public deployment needs operator
  approval** (TLS, segmentation, independent review). Treat this guide as
  preparation only; decide and authorize the actual deployment yourself.
